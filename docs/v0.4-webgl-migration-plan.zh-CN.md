## 3. 参考项目对比结论

`/Users/zj/projects/assets/fast-images-viewer` 已在 Apple M1 Max / WKWebView / 69 张 32.7MP JPEG 上验证：50 个 READY 命中样本 P50 24ms、P95 35ms、最大 39ms。其 READY 定义为 fetch → worker `createImageBitmap` → `texImage2D` → GPU fence signaled。

### 3.1 直接复用或适配的设计

- WebGL2 context attributes、shader/program/buffer 初始化；
- 明确查询 `MAX_TEXTURE_SIZE`；
- DPR-aware canvas backing size 与按需 render；
- ImageBitmap UV 方向约定，不依赖 `UNPACK_FLIP_Y_WEBGL`；
- worker resize decode，worker 不可用时主线程降级；
- `texImage2D` 后以 `fenceSync` 定义 GPU-ready；
- 单并发、可去重、可提权、可取消未开始任务的 priority queue；
- display/detail quality key 与视口/DPR 相关的资源 key；
- 按估算 RGBA bytes 的 texture LRU、protected keys 和显式 `deleteTexture`；
- ImageBitmap 上传后立即 `close()`；
- context loss 清空失效 cache、restore 后重建 GPU 资源并优先恢复 current；
- READY 命中与 miss 分开统计，后台任务延后到 current 首帧后启动。

### 3.2 不能机械复制的部分

- 参考项目只接收 Tauri asset URL；本组件必须接收 URL/Blob/bytes，并保持宿主无关。
- 参考项目 `fetch(url) → Blob` 会让已有 Blob/bytes 产生不必要复制；新 Source 层必须按输入类型选择最短路径。
- 参考项目只有 JPEG、Fit-relative zoom、简单 pan，没有本项目的 native%、zoom anchor、rotate/flip、minimap、progressive preview 和分组 Shell。
- 参考项目 React controller 直接拥有 index 与 renderer，不满足共享 Shell + media dispatcher 边界。
- 参考 cache 在极端 protected set 超预算时可继续超预算；新实现必须报告 oversubscribed 状态，并保证非 current 资源可被淘汰。
- 参考 context event 使用匿名 listener，无法在 dispose 时移除；新实现必须保存 handler 并完整 cleanup。
- 参考 `textureStatus()` 无真实 queued/running 区分；新状态机需要精确 phase 和 error。
- 参考 detail 只是 display 的 2 倍，不能保证本项目 100%/200% 时的自然像素清晰度；beta 需按实际采样密度请求更高质量资源，并明确超纹理上限时的限制。

## 4. 目标目录与依赖方向

```text
ImagePreview Shell
  ├─ core/
  │   ├─ commands + media-controller contract
  │   ├─ navigation / grouped data
  │   ├─ media-source / media-kind sniff
  │   └─ renderer-neutral zoom stop math
  ├─ ui/
  │   └─ Toolbar / Thumbnails / Minimap / EXIF / chrome
  └─ renderers/
      ├─ raster-webgl/
      ├─ svg/
      ├─ animated/
      ├─ video/
      └─ unknown/
```

依赖规则：

1. Shell 只依赖 Core contract 和 UI，不 import WebGL class、shader 或 DOM media 内部实现。
2. Dispatcher 是 Shell 唯一知道的媒体入口。
3. renderer 不拥有 `next()` / `previous()`，也不渲染 Toolbar/Thumbnails/文件名。
4. 每种 renderer 自己持有 canonical view state；Shell 只订阅只读快照。
5. Core 不保存 `cssTransform: string`、`WebGLTexture` 或 `HTMLMediaElement`。
6. 只有 Raster renderer 暴露 texture preload/cache 诊断；SVG/Animated/Video 不实现伪 preload 接口。

## 5. Media controller contract

建议内部 contract：

```ts
type ViewerCommand =
  | { type: 'zoom-in'; anchor?: ViewportPoint }
  | { type: 'zoom-out'; anchor?: ViewportPoint }
  | { type: 'set-native'; percent: number; anchor?: ViewportPoint }
  | { type: 'fit' }
  | { type: 'reset' }
  | { type: 'pan-by'; dx: number; dy: number }
  | { type: 'pan-to-natural'; x: number; y: number }
  | { type: 'rotate-cw' | 'rotate-ccw' | 'flip-horizontal' | 'flip-vertical' };

interface MediaCapabilities {
  zoom: boolean;
  nativeZoom: boolean;
  pan: boolean;
  rotate: boolean;
  flip: boolean;
  minimap: boolean;
}

interface MediaViewState {
  zoomMode?: 'fit' | 'native' | 'custom';
  zoomPercent?: number;
  fitEquivalentNativePercent?: number;
  canZoomIn?: boolean;
  canZoomOut?: boolean;
  rotation?: number;
  flipH?: boolean;
  flipV?: boolean;
  isPanned?: boolean;
  minimapGeometry?: MediaMinimapGeometry;
}

interface MediaPresentationState {
  phase: 'idle' | 'loading' | 'preview-ready' | 'display-ready' |
    'restoring' | 'unsupported' | 'error';
  error?: MediaError;
}

interface MediaController {
  execute(command: ViewerCommand): void;
  getViewState(): MediaViewState;
}
```

React 连接使用稳定 ref/`useImperativeHandle`；不使用普通 `command` prop。renderer 通过 `onViewStateChange`、`onCapabilitiesChange`、`onPresentationStateChange` 发布快照。每次切换 item/kind 时采用 generation token，旧资源的异步完成不得覆盖新 item。

Shell 的 ref API 继续保留，但内部变为 command dispatch。当前媒体不支持的命令为稳定 no-op，Toolbar 对应按钮 disabled/hidden；导航命令仍由 Shell 处理。

## 6. MediaSource 与媒体判定

### 6.1 公开数据模型

兼容演进方向：

```ts
type MediaKind = 'raster' | 'svg' | 'animated-image' | 'video' | 'unknown';

type MediaSource =
  | { type: 'url'; href: string }
  | { type: 'blob'; blob: Blob; mimeType?: string }
  | { type: 'bytes'; data: ArrayBuffer; mimeType?: string };

interface ImageItem {
  id?: string;
  src?: string;                 // 兼容入口
  source?: MediaSource;         // 新入口；存在时优先
  kind?: MediaKind;             // 宿主显式判定优先
  mimeType?: string;
  minimapSrc?: string;
  minimapSource?: MediaSource;
  // 其余现有字段保持
}
```

顶层单图 `src` 保持；后续增加对称的 `source`/`kind`。运行时要求 `src` 或 `source` 至少一个有效。已有 `{ src: string }` 用户无需迁移。

### 6.2 生命周期

- URL 直接消费，不由组件 revoke。
- Blob 直接交给 decode；DOM renderer 需要 URL 时只创建一次 lease，并在 item 切换/unmount 时 revoke。
- bytes 仅在所需 API 无法直接消费时创建 Blob；避免 ArrayBuffer、Blob、ImageBitmap、texture 四份长期并存。
- fetch response、Blob、ImageBitmap、object URL 和 texture 都有明确 owner；cache 只长期持有 texture 和必要 metadata。
- `MediaSource` 不识别 `file://` 是否可用；VS Code/Tauri 必须先提供其 WebView 可加载的 URL、Blob 或 bytes。

### 6.3 判定顺序

1. `item.kind`；
2. 对 Blob/bytes 或可安全读取的 URL header sniff：GIF、WebP animation flag、PNG `acTL`；
3. MIME family；
4. extension；
5. `unknown`。

URL sniff 使用同一次 resource load 的小头部结果，避免为了判定再完整下载。若 URL 因 CORS 无法读取 header，则回退 MIME/extension 并记录可诊断状态；跨域 Raster URL 本身也必须满足 WebGL texture 的 CORS 要求。宿主已知动画时应显式传 `kind`。

## 7. Raster/WebGL2 管线

```text
MediaSource
  → source acquire / metadata
  → optional preview decode
  → prioritized ImageBitmap decode
  → texture upload
  → GPU fence
  → cache entry display-ready
  → request render
```

核心状态与规则：

- 初次进入：preview texture 可先呈现；没有 preview 时保持空背景和 loading。
- 导航：Shell 可立即更新 index/chrome，但 canvas 继续绘制上一张 texture；incoming display-ready 后在同一 render transaction 切换。
- “已呈现”定义为 renderer 已 draw incoming，并跨过随后一个 rAF；长按导航以该 promise/backpressure 为准，不再检查 DOM `<img>`。
- 正常 idle 时不运行 continuous loop；load、resize、transform、context restore 时 invalidate 一帧。
- canvas backing size = CSS viewport × DPR；几何使用 CSS pixel，shader/quad 统一处理 rotate/flip/scale/translate。
- preview/display/detail 使用相同自然坐标和 transform，质量切换不得改变几何。
- current、next、prev 为最高保护级；更远邻居优先淘汰。自动 texture budget 按物理显示像素分为 192/256/384/512/768 MiB，4K 为 512 MiB；`preloadMemoryBudgetBytes` 是宿主显式覆盖值。
- cache key 包含稳定 item identity、source revision、quality/target dimensions；不得仅使用文件名。
- resize 使目标尺寸变化时，新 texture ready 前继续使用旧 texture；新资源 ready 后替换并释放无用尺寸。
- current 单张本身超过预算时允许临时 oversubscribed，但必须清空其它可淘汰纹理并报告状态，不能无限增长。

质量策略：Fit 优先准备 viewport × DPR × oversample 的 display texture；当 native% 导致当前 texture 采样不足时，按需请求更高质量。图片可安全放进单纹理时可提升到自然尺寸；超过 `MAX_TEXTURE_SIZE` 时 beta.1 使用最大安全降采样并给出受限状态，100% 可能不具备逐像素清晰度。真正 native fidelity 由后续 tile/LOD 完成。

## 8. 非 Raster renderer

- `svg/`：由 Source lease 产生 `<img src>`，CSS transform 只存在于该目录；支持 zoom/pan/rotate/flip，默认不 inline SVG。
- `animated/`：浏览器 `<img>` 播放 GIF/APNG/Animated WebP；自身维护 CSS transform，切换资源时释放 object URL。
- `video/`：beta.1 有目录、dispatcher 和 capabilities，显示明确“暂不支持预览”；不进入 Raster 管线。
- `unknown/`：稳定错误 UI，不尝试 WebGL decode。

自定义 `minimap: ReactNode` 保持优先级；`minimapSource` 由共享 Source lease 适配为 UI 可显示 URL。Minimap 的 transform geometry 来自当前 media viewState，点击/拖动通过 command 返回媒体模块。

## 13. 已知风险与后续边界

- beta.1 无 tile：超过单纹理上限的大图能稳定降采样显示，但 native fidelity 受限。
- 浏览器 ImageBitmap/ICC 行为不完全一致：beta 以普通 sRGB 不明显偏色为底线，P3/高级 ICC 后续增强。
- URL header sniff 和 WebGL upload 都受 CORS 约束；宿主显式 `kind` 与可加载 Source 是最可靠路径。
- Worker module 的库打包与宿主 CSP 需在浏览器、VS Code Webview、Tauri 三处验证。
- GPU memory 只有估算值；context loss、驱动分配失败和多 WebGL 应用竞争必须有可恢复错误状态。
- `minimap: ReactNode` 是现有 escape hatch，不能假设可参与 WebGL progressive preview；Raster preview 应优先使用 `minimapSource/minimapSrc`。
